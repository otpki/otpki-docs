## Driver Configuration

The driver configuration section contains the PKCS#11 Proxy-specific settings
that OTPKI uses when working with the proxy service.  For more information about
the OTPKI PKCS#11 Proxy architecture as well as how OTPKI integrates with various
commercial HSM models, refer to the [PKCS#11 Integration](../../../../../integration/pkcs11-hsms) 
page.

For PKCS#11 Proxy, the driver configuration entered on this page, including the
server address and optional config ID, is stored by OTPKI and encrypted at
rest.

<DocScreenshot
  alt="PKCS#11 Proxy key configuration driver configuration settings"
  src={driverConfigurationScreenshot}
/>

### Server Address

Use **Server Address** to specify the PKCS#11 Proxy server that OTPKI should
connect to.

### Config Id

Use **Config Id** to provide the server-side HSM configuration identifier that
the PKCS#11 Proxy service should use. Leave this blank if the proxy server does
not require a specific configuration ID.  Configuration IDs can be used to 
reference multiple slots on an HSM that have different authentication and policy, 
while still using a single PKCS#11 Proxy server instance.

For PKCS#11 Proxy, the **Encryption Key** is used to encrypt the key data
stored for each OTPKI key. This data contains the HSM key label that OTPKI
uses to reference the key through the proxy.

<ActivationSection screenshot={activationScreenshot} />

For PKCS#11 Proxy, activation is usually required because OTPKI uses the
activation code as the PIN when connecting through the proxy to list keys,
check key access, generate keys, sign, decrypt, and import HSM-backed keys.
