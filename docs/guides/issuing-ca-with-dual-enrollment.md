This guide covers two related tasks: creating an issuing CA whose key is generated by OTPKI
but whose certificate is signed by an external CA, and then setting up two distinct enrollment
paths — one for human users that requires approval, and one for automated systems that issues
certificates directly.

## Prerequisites

- OTPKI is running and accessible (see [Getting Started](../getting-started)).
- A key storage configuration exists (see [Key Configurations](../operations/issuance-and-revocation/key-management/key-configurations/index.md)).
- An external CA is available to sign the issuing CA certificate (an external root or
  intermediate CA outside of OTPKI).

---

## Step 1: Create the Issuing CA Key

Navigate to **Keys** → **Keys** and click **Create**.

| Field | Value |
|---|---|
| Name | `Issuing CA Key` |
| Description | `Private key for the externally-signed issuing CA` |
| Key Type | `ECDSA_P384` *(or your preferred algorithm)* |
| Key Usage | `SIGN_VERIFY` |
| Key Storage Config | *(select your key storage configuration)* |

Click **Create Key**.

---

## Step 2: Generate a CSR and Obtain the Signed Certificate

OTPKI can generate a Certificate Signing Request (CSR) for a key so you can submit it to your
external CA.

1. Navigate to **Keys** → **Keys** and locate the key created in Step 1.
2. Open the key's detail view and click **Generate CSR**.
3. Fill in the Subject DN fields (Common Name, Organization, etc.) as required by your external CA policy.
4. Click **Generate** — OTPKI will display and allow you to download the CSR in PEM format.
5. Submit the CSR to your external CA and retrieve the signed certificate (PEM or DER).

:::tip
Keep the downloaded CSR and the returned certificate together — you will need the certificate
file in the next step.
:::

---

## Step 3: Import the Issuing CA

Navigate to **Certificate Authorities** and click **Import**.

Select the import mode that matches what your external CA returned:

- **PKCS12** — if the external CA returned a combined key + certificate bundle.
- **PEM Upload** — if you have the certificate (and optionally chain) as separate PEM files.

For the PEM upload path:

| Field | Value |
|---|---|
| Certificate | Upload the signed CA certificate from Step 2 |
| Chain | Upload any intermediate CA certificates if needed |
| Key | *(leave blank — the key was already created in Step 1)* |
| Associated Key | Select `Issuing CA Key` from Step 1 |

Configure any additional CA settings (CRL generation, etc.) and click **Save**.

:::note
Because the key already exists in OTPKI from Step 1, select it from the **Associated Key**
field rather than uploading a key file.
:::

---

## Step 4: Create a Certificate Profile for End-Entity Issuance

Navigate to **Profiles** → **Certificate Profiles** and click **Create**.

| Section | Field | Value |
|---|---|---|
| Basic Settings | Name | `End Entity Profile` |
| Basic Settings | Certificate Type | `End Entity` |
| Basic Settings | Available CAs | *(select your Issuing CA)* |
| Validity Settings | Duration | *(e.g., `1 year`)* |
| Key Usage | Digital Signature | ✅ Checked |
| Key Usage | Critical | ✅ Checked |
| Key Identifiers | Include SKI | ✅ Checked |
| Key Identifiers | Include AKI | ✅ Checked |

Add any additional extensions (EKU, SAN, CDP, AIA) required by your use case and click **Save**.

---

## Step 5: Create an Approval Profile

Navigate to **Administration** → **Approval Workflows** → **Approval Profiles** and click
**Create**.  This profile will gate human enrollment requests.

| Field | Value |
|---|---|
| Name | `Human Enrollment Approval` |
| Description | `Requires manual approval before issuing a human certificate` |
| Number of Approvals Required | `1` *(or more, depending on policy)* |
| Approver Roles | *(select role(s) authorized to approve)* |
| Approver Groups | *(optionally select group(s))* |

Click **Save**.

:::caution
An approval profile with no approvers configured will leave requests permanently stuck.  Always
assign at least one approver role, group, or user.
:::

---

## Step 6: Create the Human End-Entity Profile

Navigate to **Enrollment** → **End Entity Profiles** and click **Create**.

| Section | Field | Value |
|---|---|---|
| Basic Settings | Name | `Human EE Profile` |
| Basic Settings | Description | `Profile for human users requiring approval` |
| Login ID Configuration | Type | *(e.g., Username-based)* |
| Password Configuration | *(configure complexity rules as required)* | |
| Subject DN | *(set required / optional fields)* | |
| Certificate Profile and CA Settings | Certificate Profile | *(select the profile from Step 4)* |
| Certificate Profile and CA Settings | Certificate Authority | *(select your Issuing CA)* |
| Approval Settings | Approval Profile | `Human Enrollment Approval` *(from Step 5)* |

Click **Save**.

---

## Step 7: Create the Automated End-Entity Profile

Navigate to **Enrollment** → **End Entity Profiles** and click **Create**.

| Section | Field | Value |
|---|---|---|
| Basic Settings | Name | `Automated EE Profile` |
| Basic Settings | Description | `Profile for automated systems — no approval required` |
| Login ID Configuration | Type | `Random` *(no human identity needed)* |
| Certificate Profile and CA Settings | Certificate Profile | *(select the profile from Step 4)* |
| Certificate Profile and CA Settings | Certificate Authority | *(select your Issuing CA)* |
| Approval Settings | Approval Profile | *(leave blank — requests issue immediately)* |

Click **Save**.

---

## Step 8: Configure Protocol Endpoints

OTPKI supports multiple enrollment protocols.  Configure one for each path.  The steps below
use **CMP** as an example; EST and SCEP follow the same pattern.

### Human Enrollment Endpoint

Navigate to **Enrollment** → **Protocols** → **CMP** and click **Create**.

| Section | Field | Value |
|---|---|---|
| Protocol Configuration | Name | `Human CMP` |
| Profile Selection | End Entity Profile | `Human EE Profile` *(from Step 6)* |
| Profile Selection | Certificate Profile | *(select the profile from Step 4)* |
| Profile Selection | Certificate Authority | *(select your Issuing CA)* |
| End Entity Authentication | Use Certificate Authentication | ✅ Enable *(or username/password)* |

Click **Save**.

### Automated Enrollment Endpoint

Navigate to **Enrollment** → **Protocols** → **CMP** and click **Create**.

| Section | Field | Value |
|---|---|---|
| Protocol Configuration | Name | `Automated CMP` |
| Profile Selection | End Entity Profile | `Automated EE Profile` *(from Step 7)* |
| Profile Selection | Certificate Profile | *(select the profile from Step 4)* |
| Profile Selection | Certificate Authority | *(select your Issuing CA)* |
| End Entity Authentication | Use Certificate Authentication | ✅ Enable |
| End Entity Authentication | Permit HMAC Authentication | ✅ Enable *(optional, for pre-shared secrets)* |
| Server Key Generation | Allow Keygen | ✅ Enable *(if OTPKI should generate and return the private key)* |

Click **Save**.

---

## Step 9: Provision Human Users

1. Navigate to **Auth** → **Users** and click **Create** for each
   human user (see [Basic User Management Guide](./basic-user-mgmt-guide.mdx)).
2. Assign each user a role that permits enrollment (e.g., a role with end-entity issuance
   permissions configured in **Permissions**).
3. If using an OIDC provider, configure it under **Administration** → **Identity** →
   **Identity Providers** with **Create Unknown Users** enabled so accounts are provisioned
   automatically on first sign-in.

---

## Step 10: Onboard Automated Entities

Automated systems authenticate via client certificate (mTLS) or CMP HMAC at enrollment time.

- **Client certificate**: issue an initial certificate to each automated system — either through
  the automated CMP/EST endpoint or pre-provisioned by your external CA — and load it into the
  system's keystore.
- **HMAC**: use the **Profile Shared Secret** configured on the CMP endpoint as the initial
  shared secret.

## Summary

| Step | What Was Configured |
|---|---|
| 1 | Issuing CA private key |
| 2 | CSR generated and submitted to external CA |
| 3 | Externally-signed Issuing CA imported |
| 4 | End-entity certificate profile |
| 5 | Approval profile for human enrollment |
| 6 | Human end-entity profile (gated by approval) |
| 7 | Automated end-entity profile (direct issuance) |
| 8 | CMP endpoints — one per enrollment path |
| 9 | Human users provisioned |
| 10 | Automated entities onboarded |
